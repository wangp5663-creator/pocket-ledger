# 小账本（pocket-ledger）设计文档

- 日期：2026-11-06
- 状态：待用户审阅
- 项目目录：`~/pocket-ledger`
- 应用显示名：小账本

## 1. 背景与目标

个人自用的移动端记账工具，包含两套**互相独立**的账本：

1. **餐补账**：每天 20 元餐补，记录实际餐费，结余逐日累计，可看到当前可动用的钱。
2. **规划账**：规划一笔支出（可分期、多笔），在某月花掉后，在之后月份逐月补回，标注事件，并记录额外汇入；完整展示「花掉 → 补回」的来回过程。

两套账都提供**按月统计**。应用部署为 PWA，在安卓手机 Chrome 中「添加到主屏幕」，离线可用，数据仅存本机（localStorage），不提供导出与云同步。

## 2. 范围

**包含**

- 餐补账：每日记录、余额累计、漏记提醒与补记、按月统计。
- 规划账：事项（事件）、多笔支出、预设补回计划、实际补回、独立汇入、事项进度与时间线、按月统计。
- 统计页：两套账的月度汇总与纯 CSS 柱状趋势。
- PWA：manifest、service worker、离线、安装到主屏幕。
- 部署到 GitHub Pages（仓库 `pocket-ledger`）。

**不包含（YAGNI）**

- 账号系统、云同步、多设备同步。
- 数据导出/导入备份（用户明确选择纯本地、不备份）。
- 系统推送通知（仅在打开应用时提示漏记）。
- 多币种、汇率。
- 编辑审计日志。
- 第三方 UI 组件库或图表库。
- 数据加密。

## 3. 核心规则

### 3.1 餐补账

- 每日餐补默认 **20 元**，可在设置中修改（存储为「分」）。
- 每天一条记录：实际花费（必填，允许 0）、备注（可选）、当天餐补额（保存时快照）。
- **余额 = Σ（当天餐补快照 − 实际花费）**，仅统计已记录且不早于起始日的日期。
- 超支直接从余额扣除，余额可为负，显示红色并标注「已超支」。
- **漏记处理**：未记录的日期不计入余额；应用内显示「还有 X 天未记录」提醒，点击进入补记，逐日填写后余额自动更新。
- **起始日期**：用户设定，默认首次使用当天；可早于今天以便补记历史。起始日期只能提前，不能晚于今天，也不能晚于最早一条已记录日期（如需重来请清空数据）。
- **修改餐补金额**：只影响今天及以后；已记录日期保留当天快照，不重算历史。
- 日期边界按设备本地时区 0 点换日。
- 金额精确到分（支持 0.5、12.30）。

### 3.2 规划账

- 独立账本，起始余额 0，金额以「分」存储。
- **余额 = Σ 汇入 + Σ 补回 − Σ 支出**，可为负，红色显示。
- **事项（事件）**
  - 字段：名称（必填）、计划总花费（可选）、备注（可选）、创建时间。
  - **支出**：可多笔（支持分期花），必须关联事项；字段：日期、金额、备注（可选）。
  - **补回**：可多笔，必须关联事项；字段：日期、金额、备注（可选）。
  - **补回计划**：事项上可预设多个月份的目标补回额（`YYYY-MM` + 金额），仅作目标，**不会自动生成流水**。
- **汇入**：不关联事项（工资、红包等），仅增加余额；字段：日期、金额、备注（可选）。
- **事项进度**
  - 已花 = 该事项所有支出之和。
  - 已补 = 该事项所有补回之和。
  - 待补 = 已花 − 已补；为负时显示「多补 X」。
  - 有计划总额且已花 > 计划总额时，显示「超计划 X」。
  - 补回计划 vs 实际：按月份逐行显示 计划金额 / 已补金额 / 差额。
- **事项时间线**：按日期合并展示支出与补回，每条后显示当时的累计待补。
- **删除事项**：二次确认，级联删除其所有支出与补回流水，余额即时重算。

### 3.3 统计

- 统计页顶部切换「餐补 | 规划账」。
- **餐补按月**：记录天数、当月餐补额度（已记录日快照之和）、实际餐费、当月结余、月末累计余额（截至当月最后一天；当月则截至今天）；柱状图展示每月结余。
- **规划账按月**：支出、补回、汇入、当月净变化（补回 + 汇入 − 支出）、月末余额（该月及之前全部流水的累计余额；当月则截至今天）；柱状图展示每月净变化。
- 两套账首页各展示本月小结（「分页表格 + 页内小结」结合）。
- 统计全部由流水实时计算，不存储冗余数据。
- 默认展示最近 6 个月，向下滚动可查看更早月份；无数据时显示空状态。

## 4. 界面设计

### 4.1 全局

- 底部导航 4 个标签：**餐补 / 规划账 / 统计 / 设置**，内联 SVG 图标。
- 移动优先，内容区 `max-width: 480px` 居中；金额使用等宽数字（`tabular-nums`）。
- **视觉规范（清新绿 + 靛蓝）**
  - 背景奶油白 `#F7F8F6`，卡片纯白，16px 圆角，柔和阴影。
  - 餐补主色薄荷绿 `#10B981`，余额卡片渐变 `#34D399 → #10B981`。
  - 规划账主色靛蓝 `#6366F1`，余额卡片渐变 `#818CF8 → #6366F1`。
  - 负数/支出珊瑚红 `#E05656`；正数用主色；正文 `#1F2933`，次要 `#6B7280`。
  - 字体栈：`system-ui, -apple-system, "PingFang SC", "Noto Sans SC", sans-serif`。
- 深色模式：通过 `prefers-color-scheme` 自动切换，使用 CSS 变量。
- 触控目标 ≥ 44px；按钮有按压态；保存成功有轻量提示动画。
- 不引入 UI 组件库或图表库；图标与柱状图为内联 SVG / 纯 CSS。
- 页面切换与弹层有轻微过渡动画，避免浮夸效果。

### 4.2 餐补页

- 顶部余额卡片：当前可用余额大数字、已记录天数、起始日。
- 今日记账卡片：日期、今日餐补额、金额输入、备注输入、保存按钮；已记录时显示今日结余并可编辑。
- 漏记提醒条（琥珀色）：还有 X 天未记录 → 补记页。
- 本月小结卡片：本月结余、当前累计余额。
- 最近记录预览（5 条）。
- 历史明细：按月分组，显示日期、花费、当日结余（±）、累计余额；点击某天可编辑/删除。
- 补记页：列出起始日至昨天的所有未记录日期，按月分组，逐日填写。

### 4.3 规划账页

- 顶部余额卡片：规划账余额、本月净变化。
- 本月小结：支出 / 补回 / 汇入 / 净变化。
- 操作按钮：「记一笔」（底部弹层选择 支出 / 补回 / 汇入；支出与补回需选择事项）、「新建事项」。
- 事项列表：名称、已花/已补/待补、进度条。
- 事项详情子页：计划与实际总览、补回计划 vs 实际逐月对比、时间线、添删支出/补回、编辑/删除事项。
- 流水编辑与删除：修改后余额与进度即时重算。

### 4.4 统计页

- 分段控件切换账本；月度列表（每行一个月）＋纯 CSS 柱状图。
- 指标与 3.3 一致；负值柱使用红色。

### 4.5 设置页

- 餐补：每日餐补金额、起始日期（只能提前）、清空餐补数据（二次确认）。
- 规划账：清空规划账数据（二次确认）。
- 关于：版本号、「数据仅保存在本机」提示。

## 5. 技术方案

- **技术栈**：Vite + React + TypeScript；普通 CSS（CSS 变量 + CSS Modules 或单一全局样式文件，保持简单）。
- **路由**：`react-router-dom` 的 `HashRouter`（GitHub Pages 刷新不 404；事项详情、补记页有独立路由，手机返回手势可用）。
- **状态**：每套账一个轻量 store（加载/变更/持久化），通过 React Context 注入；金额、日期、统计为纯函数模块。
- **金额**：内部统一用「分」整数（`number`），提供解析（元字符串 → 分）与格式化（分 → 元字符串）工具，避免浮点误差。
- **日期**：自写本地日期工具，生成 `YYYY-MM-DD` / `YYYY-MM` key；不使用 UTC 转换；处理跨月、跨年、闰年。
- **ID**：`crypto.randomUUID()`，不可用时回退到时间戳 + 随机数。
- **PWA**：`vite-plugin-pwa`（`autoUpdate`），manifest（名称、主题色、图标）、预缓存静态资源，离线可用。
- **部署**：GitHub 仓库 `pocket-ledger`，GitHub Actions 构建并发布到 Pages；Vite `base` 通过构建环境变量配置（Pages 为 `/pocket-ledger/`）。
- **测试**：Vitest + React Testing Library + jsdom；逻辑先行 TDD。
- **代码结构**
  ```
  src/
    domain/        # 纯逻辑：money, dates, meal, planning, stats
    storage/       # localStorage 读写、校验、版本迁移
    state/         # stores 与 Context
    ui/            # 页面、组件、样式
    app.tsx, main.tsx
  ```

## 6. 数据模型

```ts
type Cents = number; // 金额（分）

// localStorage key: "meal-allowance.v1"
interface MealState {
  settings: {
    dailyAllowance: Cents;
    startDate: string; // YYYY-MM-DD
  };
  records: Record<string /* YYYY-MM-DD */, {
    spent: Cents;
    note?: string;
    allowance: Cents;   // 当天餐补快照
    updatedAt: string;  // ISO
  }>;
}

// localStorage key: "planned-ledger.v1"
interface PlannedState {
  events: Array<{
    id: string;
    name: string;
    plannedTotal?: Cents;
    note?: string;
    replenishPlan: Array<{ month: string /* YYYY-MM */; amount: Cents }>;
    createdAt: string;
  }>;
  spends: Array<{
    id: string;
    eventId: string;
    date: string; // YYYY-MM-DD
    amount: Cents;
    note?: string;
    createdAt: string;
  }>;
  replenishes: Array<{
    id: string;
    eventId: string;
    date: string;
    amount: Cents;
    note?: string;
    createdAt: string;
  }>;
  inflows: Array<{
    id: string;
    date: string;
    amount: Cents;
    note?: string;
    createdAt: string;
  }>;
}
```

- 两份数据各自整体 JSON 读写；写入前做结构校验，读取到损坏数据时回退为空账并提示用户。
- key 带版本号，便于未来迁移。

## 7. 错误处理与边界

- 首次打开：引导设置起始日期（默认今天）与每日餐补（默认 20 元）。
- 金额输入：必须为非负数字，最多两位小数；非法时禁止提交并就地提示。
- 金额为空、非数字、负数、超过两位小数均拦截。
- 餐补起始日期只能提前；若选择晚于最早记录日，阻止并提示。
- 规划账：支出/补回必须选择事项；事项不存在时禁止提交。
- 补回超过已花：显示「多补 X」，不限制录入。
- 实际支出超过计划总额：标红「超计划 X」。
- 删除事项：二次确认，明确说明会连带删除支出与补回流水。
- 删除记录/清空数据：二次确认；清空仅影响对应账本。
- localStorage 不可用（无痕模式/配额满）：捕获异常，提示「无法保存数据」。
- 无网络可用：首次加载后完全离线运行；PWA 更新在下次打开时静默生效。
- 时区/系统时间被改动：新日期按本地日期生成；历史记录不受影响。
- 数据量过大：列表按需渲染/分页（按月折叠），不预优化过早。

## 8. 测试策略

- **领域逻辑（Vitest，TDD）**
  - 餐补余额：正常、超支为负、空记录、按日快照不随设置变更重算。
  - 漏记日期：跨月、跨年、起始日为过去日期、当天不计入漏记。
  - 规划账余额：汇入/补回/支出组合、可为负。
  - 事项进度：多笔支出、多笔补回、多补、超计划。
  - 补回计划对比：逐月计划 vs 实际、未录入月份。
  - 月度统计：两套账的月度汇总、月末余额、跨年。
  - 金额工具：元/分转换、两位小数、格式化。
  - 删除事项级联删除。
- **存储层**：读写往返、损坏 JSON 兜底、版本 key。
- **组件测试（少量）**：餐补记账保存与校验、规划账记一笔、事项进度展示。
- **手动验证**：同 Wi-Fi 手机连电脑开发服务 → 部署 GitHub Pages → 添加到主屏幕 → 断网打开 → 杀进程重开数据仍在。

## 9. 验收标准

1. 手机安装 PWA 后，可完成餐补每日记录，余额按规则实时更新。
2. 漏记天数有提醒，补记后余额正确更新。
3. 规划账可建事项（计划总额可选）、记多笔支出、设补回计划、记多笔补回与独立汇入。
4. 事项详情能看到「已花/已补/待补」、计划 vs 实际、完整时间线。
5. 两套账的统计页与页内小结数字准确，按月统计正确。
6. 删除/编辑流水后，余额、进度、统计即时重算。
7. 离线可用，重开应用数据不丢；界面符合第 4 节视觉规范，在手机上美观易用。
8. 单元测试全部通过，`npm run build` 无错误。
