# 小账本 v2 迭代设计：餐补阶段、恢复周期与圆团子视觉

- 日期：2026-11-06
- 状态：待用户审阅
- 基于：`2026-11-06-pocket-ledger-design.md`（v1 已实现）
- 项目目录：`~/pocket-ledger`

## 1. 背景与目标

在已完成的「小账本」上迭代餐补规则：

- 用「月度预算 / 月度保底 / 自由额度」代替单纯的每日餐补。
- 20 元阶段累计到 −150 元时提醒「没有自由额度」，切换为 15 元/天保底阶段。
- 按「恢复 20 元」的时间划分统计周期，而不是自然月。
- 引入莫兰迪配色与「圆团子 + 小盆栽」卡通形象，三种状态：真棒 / 超支 / 保底。
- 保持可维护、可调试、可更新；本次不推送部署，等实现完成后再确认。

规划账（支出/补回账本）的行为保持不变。

## 2. 范围

**包含**

- 餐补设置改为月度预算、月度保底、自由额度（自动计算）。
- 20 阶段 / 15 阶段切换、−150 阈值提醒、15 阶段起始余额重算。
- 自动恢复（每月 1 日）与手动恢复；负余额清零、正余额带入。
- 餐补统计改为「恢复周期」维度；规划账仍按自然月。
- 圆团子 + 小盆栽视觉、三种表情、状态配色、轻动效。
- v1 数据迁移到 v2。
- 单元测试、组件测试、手动验证。

**不包含**

- 规划账的任何规则/界面改动（除统计页共用布局）。
- 云同步、账号、导出备份。
- 推送通知、后台定时任务（自动恢复在打开应用时补算）。
- 蹲地哭 / 画圈圈等动作版形象（用户决定以后优化）。
- 本次部署推送（需用户再次确认）。

## 3. 规则

### 3.1 设置

- 月度餐补预算：默认 600 元。
- 月度保底：默认 450 元。
- 自由额度 = 月度预算 − 月度保底，默认 150 元（只读展示）。
- 固定按 30 天折算：
  - 日均正常 = round(月度预算 ÷ 30)，默认 20 元。
  - 日均保底 = round(月度保底 ÷ 30)，默认 15 元。
- 金额以「分」为整数存储；日均折算结果四舍五入到分。
- 校验：
  - 预算 > 保底 ≥ 0；
  - 预算 > 0；
  - 自由额度 > 0。
- 设置修改只影响**下一次恢复**；当前周期沿用周期开始时快照的预算/保底/自由额度/日均。
- 首次使用：引导设置月度预算（默认 600）、月度保底（默认 450）、起始日期（默认今天）；保存后创建第一个恢复事件，期初余额 0。
- v2 不再提供修改起始日期的入口；起始日期只用于创建第一个周期，避免周期边界混乱。

### 3.2 余额与两个阶段

- 周期内余额：
  `余额 = 期初余额 + Σ(当天餐补 − 当天实际花费)`，只统计有记录的日期。
- **20 元阶段（正常）**
  - 每天按「日均正常」累计。
  - 当某笔记录后的余额 **≤ −自由额度** 时触发：
    - 提示「没有自由额度，没有多余的钱可以随意消费」；
    - 从下一天起改为「日均保底」；
    - 15 阶段起始余额 = `当前余额 + 自由额度`。
      例：余额 −150 → 从 0 开始；−160 → 从 −10 开始。
  - 触发当天仍按日均正常结算。
- **15 元阶段（保底）**
  - 每天按「日均保底」累计，直到下一次恢复。
  - 不再有自由额度。
- **漏记**：没有记录的日期不产生当天餐补；补记后重算。漏记提醒逻辑保持 v1。
- **自由额度显示**（20 阶段）：
  - 自由额度剩余 = `max(0, 自由额度 − max(0, −余额))`；
  - 距保底金额 = `自由额度 + 余额`（余额为正时大于自由额度，表示正余额也计入可用空间）；
  - 保底阶段没有自由额度。

### 3.3 恢复 20 元

- **自动恢复**：每月 1 日 00:00（设备本地时区）。
- **手动恢复**：设置页按钮，二次确认后立即开始新周期。
- 恢复时：
  - 当前余额为负数 → 清零；
  - 当前余额为正数 → 带入新周期，作为期初余额；
  - 每天恢复为日均正常；
  - 新周期重新拥有完整自由额度；
  - 记录一次恢复事件（快照当次的预算/保底/自由额度/日均），作为统计周期起点。
- 手动恢复同样执行「负清零、正带入」。
- 同一天最多手动恢复一次；成功后在设置页提示。若当天已有自动恢复，手动恢复按钮不可用并提示「今天已经恢复过」。
- 应用打开时，如果距离上次恢复已经跨过多个 1 日，按顺序补建每个月的自动恢复事件（使用当前设置快照；这是可接受的简化）。

### 3.4 统计周期

- 餐补统计按恢复事件划分，不再按自然月。
- 每个周期显示：
  - 开始日期、结束日期（下一恢复日前一天；当前周期截至今天）；
  - 开始额度（日均正常，如 20 元/天）；
  - 是否切换过 15 阶段、切换日期；
  - 周期内实际花费；
  - 周期结束余额；
  - 结转：正数带入下期；负数显示「已清零」。
- 周期净额 = `Σ(当天餐补 − 当天花费) = 周期结束余额 − 期初余额`（未计结转清零），用于柱状图。
- 规划账统计保持自然月。

### 3.5 编辑与补记

- 新增、修改、删除、补记记录后，按日期重放整个周期，自动更新阶段与余额。
- 如果保存会导致当前阶段发生变化（20 ↔ 15），保存前弹窗确认。
- 15 阶段一旦由历史记录触发，不因为后续删除记录而自动退出，除非重算后确实不再满足触发条件。

### 3.6 数据迁移

- v1 数据（`meal-allowance.v1`）升级为 v2（`meal-allowance.v2`）：
  - 月度预算 = 原每日餐补 × 30；
  - 月度保底 = 45000 分（15 元/天 × 30）；
  - 自由额度 = 预算 − 保底；
  - 保留原起始日期与记录（记录不再依赖 allowance 快照）；
  - 在起始日期创建第一个恢复事件，期初余额 0；
  - 迁移后按新规则重放记录。
- 迁移只执行一次；迁移完成在「关于」页显示数据版本 `v2`。
- 若迁移后余额与旧版不同，以新规则为准；设置页可清空数据重新开始。

## 4. 界面与视觉

### 4.1 配色（莫兰迪 A）

- 背景：奶油白 `#F3EFE8`
- 卡片：`#FBF8F3`
- 主文字：`#4B4742`
- 鼠尾草绿（正余额/20 阶段）：`#A8B5A2` / 深 `#7E8D78`
- 陶土粉（超支）：`#D8B3A8` / 文字 `#8F3E35`
- 燕麦色（保底）：`#C9B8A0` / 文字 `#7C5A2E`
- 盆栽：陶土 `#C08B72`，叶子 `#9DB08A` / `#B7C3B0` / `#C4D0BE`
- 圆团子：奶油 `#F7F3EA`，细描边 `#D8CFC3`

### 4.2 圆团子 + 小盆栽

- 圆团子是正圆，去掉一圈圆触角和贴纸边框。
- 旁边放陶土小盆栽；盆栽叶子随状态变化：
  - **真棒**：盆栽 5 片叶子，健康。
  - **超支**：盆栽叶子掉光，地上 3 片落叶。
  - **保底**：盆栽剩 2 片叶子，地上 1 片落叶。
- 三种表情：
  - **真棒**：点眼睛、小笑嘴、腮红。
  - **超支**：眯眼（闭合实心弧），两条眼泪流下，张嘴哭，金额标红。
  - **保底**：眼睛用 `><` 形状（纠结、无高光），小圆嘴，大颗汗滴，金额琥珀色。
- 不再使用白底贴纸、圆徽章、emoji 徽章。
- 轻动效：保存后圆团子轻微弹跳、卡片淡入；支持 `prefers-reduced-motion`。

### 4.3 餐补页

- 顶部余额卡：
  - 当前可用余额大数字；
  - 状态胶囊：`20 元/天` 或 `保底 15 元/天 · 无自由额度`；
  - 圆团子 + 盆栽场景；
  - 自由额度进度条（剩余/总额）与「距保底还有 ¥X」；
  - 超支时金额标红；保底阶段金额琥珀色。
- 达到 −150 时弹一次提示：圆团子超支表情 + 「自由额度用完了，接下来按 15 元/天」，确认后关闭；页面保留「无自由额度」状态。提示只在触发当前这次保存时弹出一次；刷新或重新打开后不再弹，只显示保底状态。
- 今日记账卡、漏记提醒、周期小结、历史记录（按恢复周期分组）保持 v1 结构并适配新状态。
- 历史记录每行显示当天用的是 20 还是 15、当日结余、累计余额。

### 4.4 设置页

- 月度餐补预算（默认 600）。
- 月度保底（默认 450）。
- 自由额度（只读，= 预算 − 保底）。
- 日均正常 / 日均保底（只读）。
- 当前周期：开始日期、开始额度、是否已切 15。
- 「立即恢复 20 元额度」按钮：
  - 二次确认；
  - 提示「负数将清零、正数将带入、当天最多一次」；
  - 成功后刷新周期信息。
- 清空餐补数据、清空规划账数据（保留 v1 二次确认）。
- 关于：应用版本 `0.2.0`、数据版本 `v2`、数据仅存本机。

### 4.5 统计页

- 顶部切换「餐补 | 规划账」。
- 餐补：
  - 周期表：周期、开始日、结束日、开始额度、15 切换日、花费、结束余额、结转；
  - 周期净额柱状图（纯 CSS，负值红色）；
  - 当前周期可显示「进行中」。
- 规划账：保持 v1 的月度表格与柱状图。

### 4.6 可维护与更新

- 领域逻辑拆分为纯函数模块，便于测试和以后调整规则。
- 应用版本与数据版本在设置页可见。
- 更新通过重新部署 PWA 完成；Service Worker 仍采用「下次打开生效」的延后刷新策略。
- 本次不推送部署；完成实现和验证后再由用户确认。

## 5. 数据模型

```ts
// localStorage key: "meal-allowance.v2"
interface MealSettingsV2 {
  monthlyBudget: number;   // 分，默认 60000
  monthlyMinimum: number;  // 分，默认 45000
  startDate: string;       // YYYY-MM-DD，首次起始日
}

interface MealRecordV2 {
  spent: number;           // 分
  note?: string;
  updatedAt: string;       // ISO
}

interface RestoreEvent {
  id: string;
  date: string;            // YYYY-MM-DD，恢复生效日
  at: string;              // ISO
  openingBalance: number;  // 分，已按“负清零、正带入”处理
  monthlyBudget: number;   // 该周期快照
  monthlyMinimum: number;
  freeAllowance: number;
  dailyNormal: number;
  dailyMinimum: number;
  note?: string;
}

interface MealStateV2 {
  settings: MealSettingsV2;
  records: Record<string, MealRecordV2>;
  restores: RestoreEvent[]; // 按日期升序，至少 1 条
}
```

- 记录不再保存 `allowance` 快照；每天的额度由周期和阶段实时推导。
- 恢复事件按日期升序；当前周期 = 最后一条恢复事件至今。
- 自动恢复事件在应用打开或数据变更时补齐；手动恢复事件去重（同一天只保留一条）。
- 推导逻辑：
  - `buildMealPeriods(state, today)`：返回每个周期的逐日计算、阶段切换、结束余额、结转。
  - `currentMealStatus(state, today)`：返回当前周期、当前阶段、余额、自由额度剩余、距保底金额、15 切换日。
  - `normalizeRestores(state, today)`：补齐缺失的每月自动恢复，返回新状态（纯函数）。
- 金额一律为整数分；日均折算用 `Math.round`。

## 6. 错误处理与边界

- 数据损坏：沿用 v1 的兜底，回退为空账并提示；v2 解析失败时尝试 v1 迁移。
- localStorage 不可用：提示无法保存。
- 预算 ≤ 保底、预算 ≤ 0、保底 < 0：阻止保存并提示。
- 月初自动恢复：
  - 打开应用时补算漏掉的月份；
  - 恢复日当天 00:00 起新周期生效；
  - 如果当天已有记录，按日期边界归属到正确的周期。
- 阈值触发：
  - 触发当天仍按 20 结算；
  - 次日开始 15；
  - 同一周期只提醒一次，页面持续显示保底状态。
- 15 阶段余额为负：下个周期恢复时清零；不再追债。
- 结转：只带正余额；负余额清零。
- 手动恢复：同一天只能一次；确认文案明确负清零。
- 编辑历史导致阶段变化：保存前确认；取消则不保存。
- 31/28 天月份：日均固定按 30 天折算（用户确认），月度实际额度会略有偏差。
- 漏记日：不产生额度；补记后重算。
- PWA 更新：下次打开生效，避免刷新丢失未提交表单。

## 7. 测试策略

- **领域（Vitest，TDD）**
  - 日均/自由额度折算与校验。
  - 20 阶段余额、阈值触发、15 阶段起始余额 = B + 自由额度。
  - 触发当天/次日的额度归属。
  - 15 阶段累计、未触发时的周期结束。
  - 恢复：负清零、正带入、快照设置、手动恢复、同日去重。
  - 自动恢复：跨 1 个月、跨多个月、月初记录归属。
  - 编辑/补记/删除后重算阶段。
  - 周期统计：开始/结束、切换日期、花费、结束余额、结转。
  - 迁移 v1 → v2。
- **状态层**：打开应用补齐恢复、设置修改只影响下期、手动恢复。
- **组件**：余额卡三种状态、阈值提示、设置页手动恢复、统计周期表。
- **手动**：手机尺寸截图、PWA 离线、数据持久化、真实手机安装。
- **回归**：规划账所有 v1 测试保持通过。

## 8. 验收标准

1. 设置月度预算 600 / 保底 450 后，日均显示 20 / 15，自由额度 150。
2. 20 阶段记录花费，余额正确；跌到 −150 时提示并切到 15 阶段；15 阶段起始余额正确。
3. 触发当天按 20，次日按 15；15 阶段不再有自由额度。
4. 每月 1 日自动恢复；手动恢复可用且同日只能一次。
5. 恢复时负余额清零、正余额带入；统计周期按恢复时间划分并正确标注。
6. 三种视觉状态与盆栽叶子状态符合设计；金额颜色正确；动效可关闭。
7. 编辑/补记后阶段与余额重算，必要时提示。
8. v1 数据可迁移；旧规划账数据不受影响。
9. 全部测试通过、生产构建通过、PWA 离线可用。
10. 真机安装后完成一轮完整流程。
